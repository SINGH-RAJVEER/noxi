noxi OS is a NixOS-derived system designed to evaluate, build, activate and roll back itself with noxi, a Rust Nix engine checked byte for byte against CppNix. One configuration drives the CLI, the TUI and the NixBox desktop app, from a single laptop to a fleet.

Your configuration, written in Nix, defines persistent state. Every interface proposes typed changes, NixBox plans them against locked inputs, noxi builds them, and NixOS activation applies them as a new generation you can always leave.

The engine underneath

Compatible is a measurement,
not a promise.

noxi OS stands on an engine that must first replace CppNix 2.35.2 on existing systems. Evaluator output, derivation bytes, NAR archives, store schemas, protocol exchanges and real NixOS rebuilds are compared on the same inputs. Failures and unrun cases stay on the page.

Direction

Engine first.
Then the whole system.

An image that merely boots with noxi installed is not the goal. noxi OS is done when an installed machine can evaluate, build, activate, reboot into and roll back its own generations. New behavior stays additive throughout.

Now

noxi engine

A drop-in replacement for CppNix on existing systems: store, daemon, flakes and NixOS rebuilds through the declared matrix.
