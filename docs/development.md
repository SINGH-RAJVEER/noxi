# Development environment

This page describes the repository's current development tooling. The planned dedicated devenv equivalent, standard flake environment route, and optional native project extensions are specified separately in [native projects and development environments](development-environments.md); they are not available in the current preview. Keep using the existing devenv shell until the native tooling passes its acceptance cases.

Run `devenv shell` at the repository root to enter the Rust nightly pinned to 2026-09-20. [`devenv.nix`](../devenv.nix) is the only devenv configuration file. It reads the locked rust-overlay revision from [`flake.lock`](../flake.lock); `devenv.lock` pins devenv's own inputs. [`rust-toolchain.toml`](../rust-toolchain.toml) and the package [flake](../flake.nix) use the same nightly date. [`.cargo/config.toml`](../.cargo/config.toml) passes `-Zpolonius=next` for workspace builds, so Cargo uses the Polonius Alpha borrow checker. Rust [announced Polonius Alpha on nightly](https://blog.rust-lang.org/2026/08/04/enabling-polonius-alpha-on-nightly/); the pinned date and explicit compiler flag keep this project on that checker while it remains experimental.

The shell supplies the Rust tools (Cargo, cargo-nextest, rustc, rustfmt, Clippy and rust-analyzer), a wrapped C/C++ compiler, Make, CMake, Meson, Ninja and pkg-config for native dependencies. Cargo resolves the Rust libraries through `Cargo.lock`, including bundled SQLite and compression implementations. Repository tooling includes Nix, Jujutsu (`jj`), Git, Just, jq, ripgrep, curl, Python and uv. Use uv for Python dependencies and environments. Bash, coreutils, findutils, awk, grep, sed, tar, gzip, bzip2, xz and zstd support scripts and archive inspection; SQLite supplies database inspection tools. QEMU supplies `qemu-img` and KVM VM tools, and socat connects to the reference VM monitor. The reference VM launcher still uses its own Nix-built QEMU package. Entering the shell does not build the pinned CppNix or static BusyBox test artifacts; run `just reference` for those.

The checked-in [`.envrc`](../.envrc) enters the same shell through direnv after `direnv allow`. The shell disables the optional dotenv setup hint; dependency and compiler pins remain in their lock files.

Run `just` to list recipes. `just fmt-check` checks formatting, `just check` type-checks the workspace, `just test-fixtures` runs the copied CppNix fixture checks, including every language fixture against the evaluator ([outcome table](verification.md)), and `just test` runs the full workspace suite. Tests run under [cargo-nextest](https://nexte.st); `just test` follows it with `cargo test --doc` because nextest does not run doctests. `just ci` runs formatting, the offline snapshot check, type checking, and the full suite in sequence.

The local tests also cover behavior outside the copied Nix suite. `cargo nextest run -p nix-rs-cli --test cli` checks the preview command's arguments, strict evaluation, file handling, and exit codes. `cargo nextest run -p nixrs-compat-tests --test differential_eval` checks the comparison runner with mock executables, including its isolated environment, JSON report, mismatch handling, and version failure. These tests need no CppNix executable. The runner tests use POSIX shell mocks and run on Unix.

`just vm-test` builds the flake's `nixrs` package and runs the NixOS VM test in [`tests/vm/`](../tests/vm/) through the NixOS test driver. It needs KVM and the `nixos-test` system feature, and it is also the `vm` flake check, so `nix flake check` boots it. `just vm` opens the same machine in the interactive driver; call `start_all()` and then `machine.shell_interact()`, or `test_script()` to replay the check. `just ci-vm` runs `just ci` and then the VM test. The package source is limited to `.cargo/`, `Cargo.toml`, `Cargo.lock` and `crates/`, so editing the test script or the docs reuses the built binary. Flakes read only tracked files, so a new file under `tests/vm/` has to be tracked before the check sees it. [System tests](verification.md#system-tests)

Run `just nix-tests-update` to fetch the latest numbered stable official Nix source and tests into the ignored `tests/nix-official/` checkout. The command updates `tests/nix-official.lock` with the exact tag and commit. Run `just nix-tests-sync` after cloning this repository to restore that revision. The fixed 2.35.2 fixtures used by the Rust compatibility tests remain under `tests/nix/`; updating the official checkout does not rewrite them. Run `just nix-snapshot-refresh` afterwards to copy the checkout's test paths into `tests/nix/` and rewrite `tests/nix-snapshot.lock`. Run `just nix-snapshot-verify` to check those fixtures against the object IDs recorded for their upstream commit, or `just nix-snapshot-verify upstream` to also compare with the fetched commit. [Test snapshot](verification.md#test-snapshot)

The imported `nix-compat-derive-tests` trybuild UI snapshots were captured under Rust 1.95 and have been updated for the pinned nightly's diagnostics. `deserialize_enum_non_exaustive.rs` used to trigger a rustc internal compiler error; `nix-compat-derive` now reports the uncovered version before generating the code that crashed the compiler. Never bless a compiler crash into a snapshot. `just test-core` skips the toolchain-sensitive UI snapshot crate for quick runs; it does not replace `just test` as the complete check. The copied CppNix shell and NixOS VM tests still need dedicated runners, as described in [verification](verification.md).

Run `devenv shell -- just ci` for the complete Rust workspace; it passes on the pinned toolchain. Keep any nightly-specific UI snapshot changes separate from compatibility logic so reviewers can see which diagnostics changed.
# Pure evaluator comparison

Performance work follows the [architecture plan](performance.md), [benchmark protocol](performance-benchmarks.md), and [scenario catalog](../benchmarks/catalog.tsv). The [runner](../benchmarks/README.md) implements 38 offline subsets and records unsupported cases. Use `devenv shell -- just bench-build`, `bench-test`, `bench-list`, and `bench`; Python runs through uv. Timings compare identified release artifacts and exclude setup/build commands. Existing differential checks supply correctness oracles; they do not establish speedups.

Run `just reference` to build the pinned CppNix 2.35.2 reference at `target/nix-reference` and the statically linked busybox that the build comparisons in `reference_build` use as their builder at `target/test-busybox` (the flake's `test-busybox` package, from the pinned Nixpkgs). The flake input `nix-reference` locks tag `2.35.2` without overriding its inputs, so the package is upstream's own build and is fetched from cache.nixos.org. Run `just eval-compare-reference` to compare the preview evaluator with it, or use `just eval-compare /path/to/nix-instantiate /path/to/report.json` from `devenv shell` to compare a small pure-expression corpus against another explicitly selected CppNix executable. The command writes a JSON report and fails if exit codes, stdout, or stderr differ. Record the reference revision separately when using this for compatibility evidence; the host Nix version may differ from the 2.35.2 reference. See [verification](verification.md).
