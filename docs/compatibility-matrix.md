## Engine continuation evidence, 2026-11-13

The integrated debug binaries built with `CARGO_BUILD_JOBS=2 cargo build -p noxi-commands --bins`. Engine library tests passed 41 tests with one ignored; `reference_build` passed 22 with one ignored, including floating CA outputs, self references, input resolution and realisation rows. `reference_store_dir` passed its environment-directory and unsandboxed-build comparison. Standalone LZMA cache decompression now uses the existing Rust decoder; its independently generated standalone-format fixture and truncated-header rejection test passed. Compressed cache uploads remain unsupported by the command interface.

The full `upstream_functional` run used CppNix 2.35.2, two concurrent scripts, 120-second timeouts and preserved scratch directories. It executed 428 engine/script combinations and recorded 51 pass, 149 gap, 12 anomaly and two unrun scripts. The expectation table now reflects those measured outcomes, including reference anomalies. The initial test invocation failed because the previous table was stale; it was not rerun after the evidence-based table refresh. Logs, the complete JSON report and per-executable SHA-256 hashes are preserved at `/tmp/noxi-engine-20261113/functional-results/`; command logs and build logs are in `/tmp/noxi-engine-20261113/`. The runner hard-links candidate binaries before execution, so its hashes identify that run even though the subsequent integrated rebuild includes the LZMA decoder and concurrent command-owner fixes. The complete functional table does not qualify that later rebuild.

CA construction remains rejected by `noxi-glue/src/derivation.rs` for `__contentAddressed`; the shared compatibility `OutputsBuilder` supports only fixed and input-addressed outputs. Backend CA differential success does not close this construction gap. Fresh-build JSON remains explicitly rejected by the command layer because its build API lacks result metadata. Frequent functional failures also include builders referring to unavailable BusyBox paths, compressed cache uploads and unsupported cache-store opening. Final legacy-store differential validation passed two tests and failed one on existing-directory `--restore` diagnostic wording; the exact repro and log were sent to the command owner. No command/evaluator files, host services, commits or publication were changed by this engine continuation.


## Explicit compressed cache uploads, 2026-11-13

The engine cache upload API now honors explicit `compression=gzip`, `compression=bzip2` and `compression=zstd` URI parameters. It stages compressed bytes before publication, computes `FileHash` and `FileSize` over those bytes, and retains `NarHash` and `NarSize` over the original NAR, following the separation in pinned CppNix 2.35.2 `binary-cache-store.cc`. Signed closure export and atomic publication retain their existing checks. The engine API default remains uncompressed; the command owner integrated an explicit codec allowlist and continues rejecting unspecified/default compression pending separate default-policy qualification. Unsupported upload codecs fail before writing cache objects; read caches remain usable with other compression parameters.

`CARGO_BUILD_JOBS=2 cargo test -p noxi-compat-tests --test reference_substitute compressed_local_uploads -- --test-threads=1` passed one test, exporting a signed closure in all three formats and requiring the pinned reference to substitute it and pass `nix-store --verify --check-contents`. The store library suite passed 19 tests before the final read-parameter validation adjustment; the reference test compiled and exercised that adjustment. Logs are `/tmp/noxi-engine-20261113/compressed-reference.log` and `compressed-store-tests.log`. This closes the explicit gzip/bzip2/zstd API gap, while XZ/LZMA uploads, compression defaults and the complete upstream compression script remain unqualified. The earlier full functional counts qualify their recorded candidate, not this later change.
